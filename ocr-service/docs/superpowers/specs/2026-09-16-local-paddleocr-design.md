# 本地 PaddleOCR 服务设计

**日期：** 2026-09-16  
**范围：** 员工档案与人事流程管理平台的第一阶段本地 OCR 核心能力。

## 1. 目标与边界

本阶段交付一个可由后续人事业务后端调用的 Python/FastAPI 本地 OCR 服务。服务接收 PNG、JPEG 图片，保存原图，使用 PaddleOCR 的中文模型识别文字，并返回文本、坐标、置信度、任务状态和可查询的任务结果。

服务不负责身份认证、角色权限、档案业务状态、审批、人事主数据或数据库关系维护。这些能力属于未来业务系统；OCR 服务仅通过 `taskId` 提供可关联的识别证据。

固定表单的字段映射、格式校验、低置信度字段提示和人工修订将建立在本阶段稳定的原始识别结果之上。本阶段不再返回 mock 字段，也不将 OCR 原始结果直接写入任何人事主数据。

## 2. 对外接口合同

保持现有接口路径和响应包络不变，降低业务系统联调成本。

### 2.1 创建并同步识别任务

`POST /api/ocr/tasks`

- 请求：`multipart/form-data`，仅包含 `file`。
- 支持：PNG、JPEG。
- 成功：HTTP 200、`code: 0`，任务状态为 `SUCCEEDED`，包含 `textBlocks`。
- 业务失败：识别异常时仍返回 HTTP 200、`code: 0`，任务状态为 `FAILED`，保留原图和错误原因。
- 输入失败：不支持的 MIME、无效图片、超出文件大小限制时返回 HTTP 400 和确定的错误码。

### 2.2 查询任务

`GET /api/ocr/tasks/{taskId}`

- 成功：返回已保存的任务和识别结果。
- 不存在：HTTP 404，`code: "TASK_NOT_FOUND"`。

### 2.3 结果格式

每条文本块结构为：

```json
{
  "pageNo": 1,
  "text": "张三",
  "confidence": 0.98,
  "bbox": [32, 68, 166, 104]
}
```

- `bbox` 使用原图像素坐标 `[left, top, right, bottom]`。
- `confidence` 保留 OCR 模型原始置信度，范围应为 0 到 1。
- `fields` 在本阶段固定为空数组，避免输出并不存在的业务字段。
- 后续字段抽取服务以 `textBlocks`、原图和 `taskId` 为输入，产生可修订、可追溯的字段版本。

## 3. 架构与职责

```text
FastAPI 路由
  -> 文件类型、大小和内容校验
  -> OcrService（原图持久化、任务状态编排）
  -> PaddleOcrEngine（预处理、PaddleOCR 调用、结果归一化）
  -> TaskStore / SourceFileStore
```

- `app/main.py`：仅处理 HTTP 输入输出与异常码。
- `app/service.py`：保存原图、维护 `RECOGNIZING`、`SUCCEEDED`、`FAILED` 任务状态。
- `app/engines.py`：封装 PaddleOCR，屏蔽 PaddleOCR 版本返回差异；统一输出 `RecognitionOutput`。
- `app/store.py`：分别保存源文件与任务元数据，避免把图片字节放入任务对象。
- `app/config.py`：集中处理环境变量和引擎配置。

此边界允许以后将任务仓库替换成数据库或将 OCR 引擎替换为其他本地/云引擎，而不变更 HTTP 合同。

## 4. PaddleOCR 与图像处理

### 4.1 引擎配置

- 默认 `OCR_ENGINE=paddle`。
- PaddleOCR 与 PaddlePaddle 是运行时必需依赖，应用启动时加载失败应给出明确可操作的错误。
- 测试中通过注入轻量伪引擎避免下载模型或依赖硬件。

### 4.2 图像预处理

引擎在识别前执行最小且确定性的预处理：

1. 基于 EXIF 自动旋转，纠正手机拍摄的方向信息。
2. 转换为 RGB，消除 PNG 调色板、透明通道或灰度模式差异。
3. 当图片最长边超过配置阈值时等比例缩小，限制模型输入和内存占用。
4. 写入临时预处理文件后调用 OCR，识别结束后清理临时文件。

不在本阶段使用激进的锐化、二值化或自动裁剪，避免改变坐标参考系、误伤低质量材料或为后续坐标标注引入偏差。

### 4.3 结果归一化

兼容 PaddleOCR 常见的新旧返回格式，将每行文字转换为 `TextBlock`：

- 多边形坐标取最小/最大横纵坐标，形成矩形 `bbox`。
- 缺少坐标或置信度时分别使用 `[0, 0, 0, 0]` 和 `0.0`，但不丢弃可用文本。
- 空白文本将忽略，避免返回无意义文本块。
- 同一图片只作为单页处理，统一返回 `pageNo: 1`。

## 5. 配置与依赖

环境变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `OCR_ENGINE` | `paddle` | OCR 引擎标识。开发期可显式设为 `mock`。 |
| `OCR_DATA_DIR` | `./data` | 上传原图保存目录。 |
| `OCR_MAX_FILE_SIZE_BYTES` | `10485760` | 上传文件大小上限。 |
| `OCR_MAX_IMAGE_EDGE` | `4096` | 预处理后图像最长边上限。 |
| `OCR_HOST` | `127.0.0.1` | Uvicorn 监听地址。 |
| `OCR_PORT` | `8000` | Uvicorn 监听端口。 |

生产/演示运行安装 `paddlepaddle` 与 `paddleocr`；将其记录在可选依赖组和安装文档中，避免在不支持 Paddle 的环境里使单元测试不可运行。

## 6. 异常处理与可追溯性

- 图片验证失败、大小超限、类型不支持使用确定错误码并在路由层返回 400。
- 引擎初始化失败应阻止以 `paddle` 模式启动，避免服务看似可用却只能返回 mock 数据。
- 识别过程中异常时保存任务状态 `FAILED`、错误信息、原图元数据和 SHA-256；查询接口可复现失败证据。
- 识别成功时保存原图哈希、文本块、置信度和坐标。后续业务系统据此保存人工修订、字段版本和审计日志。

## 7. 验收与测试

1. 单元测试：Paddle 返回结构转换、四点坐标归一化、空文本过滤、预处理尺寸/方向逻辑。
2. API 测试：PNG/JPEG 上传、输入校验、成功任务可查询、识别失败保留原图、OpenAPI 合同。
3. 启动测试：显式 `OCR_ENGINE=mock` 的轻量启动测试继续可用；真实 Paddle 依赖缺失时，`OCR_ENGINE=paddle` 启动失败信息明确。
4. 本地人工验收：安装 Paddle 依赖后，使用脱敏中文图片调用上传接口，响应中至少含一个非空 `textBlocks` 文本，并能以 `taskId` 查询到相同结果。

## 8. 非目标与后续迭代

不在本次变更实现数据库任务仓库、PDF/Office 文档、多页 OCR、异步队列、业务字段模板、格式校验规则、低置信度字段状态、人工修订界面、鉴权或审批流程。

下一阶段在本服务的原始识别结果之上增加：材料类型模板、字段定位/映射、规则校验、低置信度标识、修订记录，并由业务系统负责关联档案版本、人员和审批流程。
