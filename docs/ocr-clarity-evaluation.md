# OCR 清晰度评测记录

## 本轮评测

- 日期：2026-10-11
- 引擎：本机 PaddleOCR，任务记录版本为 3.7.0；项目固定 PaddlePaddle 3.3.0
- 样本生成器：`scripts/evaluate-ocr-clarity.py`
- 数据来源：`ocr-service/tests/fixtures/platform-smoke.png` 派生的合成图像
- 覆盖：4 组姓名与员工编号 × 3 种版面 × 3 种清晰度，共 36 张图像；每张核对姓名、员工编号两个字段
- 版面：原版、加边框及分隔线、轻微旋转
- 指标：字段检出率、字段准确率、任务失败率和 OCR 处理平均耗时

字段准确率为识别值与真值完全一致的字段数除以期望字段数；字段检出率为返回的目标字段数除以期望字段数。任务失败率按 OCR 任务状态统计。平均耗时来自 OCR 任务记录，不包括图像生成、上传、网络等待或人工复核。

脚本还覆盖了 `PLAIN`、`BORDERED`、`SKEWED` 三种版面，每种 12 张。评测 API 按清晰度分组统计，当前没有单独计算版面分组准确率，因此不据此比较版面之间的性能。

本次评测的原始 JSON 保存在 `/tmp/ocr-clarity-eval-20261011.json`。评测请求只临时提交合成样本的真值，服务不把真值写入 OCR 任务库。低清晰度组耗时较短是这次运行的观测结果，不表示低清晰度图片更容易识别；推理耗时会受到模型缓存、进程负载和运行顺序等因素影响。

## 失败场景覆盖

这 36 张有效合成图片均识别成功，评测集本身没有产生任务级失败。服务的独立自动化测试覆盖内部令牌缺失时拒绝请求、无效图片和不支持格式、识别异常时保留原图和错误信息，以及检测预览生成失败等路径。评测准确率不能代替这些异常路径测试，也不将 HTTP 拒绝请求计作 OCR 任务失败。

Spring Boot 发起档案 OCR 时从当前登录主体传入 `operatorId`；字段修订也使用登录用户 ID 记录操作人，不接收浏览器任意指定的操作人身份。

## 限制与后续

样本均从单张合成底图生成，姓名和编号只有四组，字段类型只有两种；它们不是独立采集的真实扫描件。当前评测未覆盖手写内容、严重遮挡、阴影、透视畸变、复杂表格、身份证号和手机号等字段，也没有报告置信度分布、低置信度召回率或人工修正率。100% 仅描述此小样本，不能外推为真实企业材料准确率。

该轮指标来自评测时已运行的 `127.0.0.1:8000` PaddleOCR 服务。其识别引擎及样本流程得到实测，但本轮 OCR API 令牌中间件是否已加载到该进程没有可复现证据；令牌保护已由当前源码对应的 API 测试覆盖。后续正式论文实验应在重启后的当前版本服务上重跑并归档 JSON，同时记录代码提交、模型版本、硬件环境、样本集版本和人工标注规则。

正式实验应在获得脱敏样本授权后纳入多个版式与成像来源，由人工双重核验字段真值，分别统计准确率、检出率、失败原因、置信度分层和人工修订率。不得将本合成集结果表述为生产数据结论。
