# 员工自助注册设计

## 目标

允许已有在职员工自助创建登录账号，并在注册成功后立即获得员工工作台权限。

## 方案

公开注册接口接收密码、姓名和预留手机号。服务端必须用姓名和预留手机号唯一匹配一条在职员工档案，部门、员工 ID 和登录用户名均从档案读取；客户端不能提交员工编号、员工 ID、部门、用户名或角色。匹配成功后，服务端在事务中锁定员工档案，检查该员工是否已有账号，使用 BCrypt 保存密码，启用账号并只分配 `EMPLOYEE` 角色。员工编号由人事新建档案时由服务端生成，并作为员工的登录用户名。

注册接口返回与登录一致的 `AuthResponse`，前端保存会话并进入员工工作台。用户名冲突和员工资料不匹配使用明确的业务错误；员工资料不匹配或已绑定账号使用统一提示，避免泄露档案是否存在。密码不落日志。

## 影响范围

- Spring Security：仅开放 `POST /api/auth/register`。
- Auth 模块：请求校验、员工档案匹配、账号创建、角色分配和 JWT 返回。
- MyBatis：增加带行锁的姓名/手机号在职员工查询和员工账号计数。
- 员工档案：新建档案时生成唯一员工编号，不再接收客户端编号。
- Vue：新增注册表单和公开路由，在登录页增加注册入口，注册成功后自动登录。
- 不新增表或迁移；复用现有员工档案、账号、角色关系和 BCrypt 配置。

## 验收标准

- 只有姓名和预留手机号唯一匹配到现有在职员工档案时才能注册；没有匹配或匹配多条都拒绝。
- 人事创建员工档案时由服务端生成员工编号并在成功响应中返回。
- 单个员工最多有一个自助注册账号；注册账号为启用状态且角色只有 `EMPLOYEE`。
- 账号名已存在、员工资料无效、员工已绑定账号时不创建部分数据。
- 注册成功后可立即访问员工应用端；不能通过注册请求提升为其他角色或更改员工部门。
- 登录页提供注册入口，注册页不要求员工编号或用户名，只收姓名、档案手机号和密码，提供重复密码校验、服务端错误提示和提交状态。
