# 平台管理与组织岗位维护设计

**日期：** 2026-10-01  
**状态：** 按已确认的毕设需求基线实施  
**范围：** 补齐组织/岗位维护与系统账号角色分配，不改变既有 OCR 服务和业务流程状态机。

## 目标

完成组织岗位与账号角色的管理闭环，使系统管理员和人事管理员能够维护业务主数据，系统管理员能够创建和维护演示账号。接口从认证主体校验权限，写操作记录操作日志；界面与后端权限保持一致。

## 功能与规则

### 部门和岗位

- 人事管理员、系统管理员可新增和编辑部门及岗位；部门负责人和员工只读。
- 部门字段包括编码、名称、上级部门、负责人、排序和启用状态；禁止设置自身或下级部门为上级，禁止停用仍含启用子部门或在职员工的部门。
- 岗位关联单一部门，字段包括编码、名称和启用状态。停用岗位保留历史员工引用，但不再出现在新员工和调动申请的可选项中。
- 采用停用而非物理删除，保留员工、流程和审批历史中的关系。

### 账号和角色

- 仅系统管理员可查看、创建和维护账号；列表仅返回账号、绑定员工/部门、启用状态和角色，不返回密码哈希或无关个人字段。
- 新账号使用 BCrypt 保存密码。普通员工、部门负责人和人事账号必须绑定在职员工，账号部门须与员工部门一致；系统管理员账号允许不绑定员工。
- 更新时角色集合为完整替换；仅允许分配启用的已知角色。改绑员工时同时校验员工状态和部门一致性。
- 任何操作都不能停用最后一个启用的系统管理员，也不能移除最后一个系统管理员的角色。并发变更通过锁定系统管理员角色行串行化。
- 角色/账号更新不撤销已签发 JWT；权限变更在账号下次登录时生效。管理员界面需明确展示这一点。

## API 与页面

- 组织 API 在现有 `/api/departments` 下增加管理查询、新增/更新部门及岗位接口；原 `/tree` 与 `/{departmentId}/positions` 仍只返回启用数据。
- 账号 API 新增 `/api/admin/users` 分页列表、创建、更新和角色选项接口，全部由 `SYSTEM_ADMIN` 保护。
- 前端新增组织岗位管理页和账号角色管理页。导航按角色显示，路由也检查角色；任何权限结论最终由服务端接口执行。
- 统一响应、参数校验、业务异常、traceId 和审计沿用现有基础设施。

## 验收

- 后端测试覆盖角色拒绝、员工/部门关系校验、部门循环与停用约束、重复编码、账号密码哈希、角色替换、最后管理员保护和审计。
- Mapper 持久化测试覆盖 SQL 过滤、写入和事务关系。
- 前端测试覆盖角色导航、管理表单提交、校验提示、空状态与接口失败状态。
- 使用现有演示服务验证人事/系统管理员成功操作、普通角色被拒绝，并确认账号与组织数据可被业务页面读取。

## 数据与隐私

复用现有 `org_department`、`org_position`、`sys_user`、`sys_role` 与 `sys_user_role` 表，不收集额外个人信息。新增账号与组织变更均写入 `operation_log`；列表和审计不暴露密码、完整 OCR 原图或对象存储 key。
