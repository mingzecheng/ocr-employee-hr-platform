# 前端工作台完善设计

## 目标

围绕“员工档案 -> OCR 识别 -> 人工复核 -> 人事流程 -> 授权与盘点”的业务闭环，完善现有 Vue 前端的工作台、员工列表、档案证据和 OCR 复核体验。界面保持商务风格，以深蓝和浅蓝灰为主色，保证桌面端与 390px 移动端可用。

## 当前问题

- 概览页只有静态统计和待办摘要，缺少明确的快捷操作和可继续处理的入口。
- 员工列表调用 `GET /employees?page&pageSize`，但后端只返回数组，前端固定读取第 1 页 100 条，无法表达总数，也会遗漏超过 100 条的员工。
- 员工列表没有新建员工操作，加载失败只能通过消息提示恢复。
- 档案详情已能上传、预览和修订，但 OCR 字段没有低置信度筛选、复核状态汇总，结果区域在数据较多时不利于快速定位风险字段。
- 各页面已有加载、空数据和错误态，但视觉和操作反馈不完全统一。

## 设计方案

### 1. 工作台概览

保留现有四项指标和待办摘要，增加一组基于权限的快捷操作：新建员工、人事申请、档案授权、发起盘点。每个快捷操作直接跳转到对应页面或打开对应表单。最近员工列表显示状态和档案入口，OCR 质量区显示成功率、失败任务和待复核数量，并在统计接口失败时保留可读错误态。

### 2. 员工列表与服务端分页

将员工列表接口的数据改为分页对象：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

后端继续接收 `page` 和 `pageSize`，按当前数据权限计算总数；前端在服务端分页基础上保留姓名/编号/状态筛选，筛选条件变化时回到第 1 页并重新请求。为兼容当前页面测试和迁移过程，API 解包层可识别旧数组响应，但生产接口统一返回分页对象。

员工列表增加“新建员工”表单，字段包括员工编号、姓名、身份证号（可选）和部门 ID（可选），提交成功后关闭表单、刷新当前页并给出成功反馈；重复编号、权限不足和网络错误展示在表单内。

### 3. OCR 证据复核

在 OCR 结果面板中增加：

- 结果状态摘要：识别状态、检测块数量、结构化字段数量、低置信度字段数量。
- 字段筛选：全部字段、低置信度字段、未检出字段；低置信度阈值固定为 80%，空置信度视为待复核。
- 复核操作：字段进入编辑态后保存人工修订，成功后保留字段校验状态和“已修订”视觉标记；失败时保持编辑值并显示错误。
- 检测框效果图继续从后端按 `bindingId` 拉取，保留重新加载和下载；原始影像由档案详情页提供，两个区域通过标题和文件名明确区分。

### 4. 统一视觉与响应式

扩展现有 CSS 变量和工作台样式，不引入新的 UI 框架。统一以下元素：

- 页面标题区、工具栏、主按钮和图标按钮的间距与焦点态。
- `loading / empty / error / success` 四类反馈状态。
- 统计卡片、表格、表单、状态标签和分页条。
- 760px 以下导航换行，双栏业务页面改为单栏，表格操作保持可触达且不发生横向遮挡。

## 数据与错误处理

- 所有新增请求沿用现有 `http`、JWT 和 `unwrap` 封装，不在页面中直接拼接认证头。
- 后端分页查询和新建员工沿用既有数据权限与权限标识：`PERM_ARCHIVE_READ`、`PERM_ARCHIVE_WRITE`。
- 表单提交期间禁用重复提交；失败时保留用户输入，成功时刷新服务端数据。
- OCR 复核失败不清空当前结果或编辑内容；低置信度和异常状态不能只依靠颜色表达。

## 实现边界

- 本次不重写路由、认证、Element Plus 基础组件和已有流程页面。
- 本次不引入图表库之外的新运行时依赖；概览继续使用已有统计接口。
- 后端仅修改员工分页返回结构及其查询/测试，不改变数据库表结构。

## 测试与验收

- 后端：员工分页响应、总数计算、数据权限和旧接口异常路径测试。
- 前端：员工新建提交、分页切换、筛选重置、加载失败重试、OCR 低置信度筛选和字段修订失败保持编辑态。
- 全量执行 `npm test -- --run` 和 `npm run build`。
- 使用浏览器验证桌面端和 390px 移动端：概览快捷操作、员工分页、新建员工、档案 OCR 复核和检测框预览。
