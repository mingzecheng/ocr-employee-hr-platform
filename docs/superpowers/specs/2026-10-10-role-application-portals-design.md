# 基于用例角色的多应用端设计

**日期：** 2026-10-10  
**状态：** 按用户授权的需求分析方案推进  
**范围：** 前端入口、页面信息架构、角色授权边界和用例文档

## 1. 复核结论

当前 `web/src/App.vue` 将登录以外的路由统一放进一个 `AppLayout`。侧栏虽然按角色过滤，但员工、部门负责人、人事管理员和系统管理员仍访问同一个路由树与首页；多数路由允许所有角色进入，部分页面再隐藏操作按钮。多角色账号可以保存多个角色，却没有选择或切换业务工作台的能力。

当前角色模型也把系统管理和 HR 业务职责混在一起：`SYSTEM_ADMIN` 被授予员工、档案、OCR、流程审批、档案授权和盘点接口的操作权限，数据范围解析为 `ALL`；它可以执行 HR 最终审批和部门审批。这样，独立系统管理角色同时成为所有业务角色的超级角色，无法体现职责分离。

登录页仍提供演示账号回填入口，与“登录页不放样例”的既有需求冲突。现有共享概览页同时展示员工、档案完整率、HR 流程、授权异常和 OCR 指标，也没有按角色区分首屏任务。

## 2. 目标

提供四个具有独立入口、首页、导航和路由授权的用户应用端：

| 应用端 | 主要用户 | 主要目标 |
| --- | --- | --- |
| 员工自助端 | 企业员工、业务经办人员 | 维护本人事务，提交人事申请，申请档案访问，完成本人档案借用和归还 |
| 部门工作端 | 部门负责人 | 处理本部门审批、员工和档案范围查询、部门盘点与差异处置 |
| 人事运营端 | 人事管理员 | 维护员工与档案、OCR 复核、人事复核、离职交接、档案授权、合同与企业统计 |
| 系统管理端 | 系统管理员 | 管理账号角色、组织结构配置、平台审计和聚合运行概览 |

四个入口继续共用一个前端仓库、Vue 组件、认证状态和 Spring Boot API。每个入口是独立的多页面构建入口，不是同一应用中的角色皮肤；业务 API 仍由服务端角色和数据范围校验。

## 3. 页面与导航

### 3.1 员工自助端

- 首页显示本人待办、申请状态、档案访问与归还提醒。
- 本人档案只展示授权字段及可访问版本。
- 人事申请提供本人或经办范围内可提交的申请类型，并显示申请详情和审批进度。
- 档案授权页面支持发起访问、使用、归还和移交。
- 合同台账为本人数据范围的只读视图。
- 只允许查看本人或已授权范围内现存的 OCR 结果；触发、复核和重新识别操作不出现在员工端。
- 390px 以上移动端优先，底部主导航最多五项。

### 3.2 部门工作端

- 首页将本部门待审批申请、待办和盘点异常作为首屏重点。
- 员工与档案按部门范围查询，敏感字段继续由服务端脱敏。
- 人事流程页面可查看本部门申请并完成部门审批，不显示 HR 最终审批动作。
- 盘点页面仅处理本部门盘点任务和异常。
- 档案申请与本人事务保留，档案借用按原有授权流程完成。
- 桌面端采用密集列表和审批队列；移动端保留待办处理能力。

### 3.3 人事运营端

- 首页突出人事审批、待复核 OCR、离职交接、档案授权和合同到期提醒。
- 管理员工主数据、员工档案、材料版本和 OCR 结果；仅人事人员进行人工修订和失败重试。
- 审批人事流程 HR 节点并确认离职交接。
- 审批档案访问并处理企业级盘点、合同和统计。
- 组织岗位入口只维护 HR 工作所需的组织结构；账号角色不放在人事端。
- 桌面端为日常运营控制台，默认先显示队列和异常，不用通用统计卡片取代待办。

### 3.4 系统管理端

- 首页显示账号与角色配置、组织配置入口和聚合审计信息。
- 账号管理仅系统管理员可访问；组织结构按现有接口能力由系统管理员或 HR 管理员维护。
- 审计日志保留 HR 与系统管理员读取权限。
- 不默认提供员工档案、OCR 修订、HR 业务审批、授权审批和盘点操作。
- 需要兼任 HR 或部门审批职责时，为账号显式分配相应角色；登录后可切换到对应应用端。

## 4. 入口和认证

- 根入口 `/` 只承担登录与工作台选择，不承载 HR 业务页面。
- 员工、部门、人事、系统管理分别使用独立 HTML 入口，使用 Hash 路由避免静态服务器为每条子路由增加 rewrite 规则。
- 单角色账号登录后直接进入唯一应用端；多角色账号进入工作台选择页。
- 每个应用端有独立路由表和允许角色列表；越权直达 URL 显示无权限结果并返回工作台选择页。
- 页面切换工作台只展示账号已被分配的角色，不更改 JWT、不提升权限。
- 所有入口使用同一 JWT/API 客户端，不把角色选择当成服务端授权凭据。
- 移除登录页演示账号回填；模拟账号只写入脱敏演示手册。

## 5. 角色授权矩阵

| 业务能力 | EMPLOYEE | DEPT_MANAGER | HR_ADMIN | SYSTEM_ADMIN |
| --- | --- | --- | --- | --- |
| 本人业务与档案 | 本人 | 本人/本部门 | 企业范围 | 不默认开放 |
| 部门人员和档案 | - | 本部门 | 企业范围 | 不默认开放 |
| 员工主数据和材料维护 | - | - | ✓ | 仅显式兼任 HR |
| OCR 触发、复核与修订 | - | - | ✓ | 仅显式兼任 HR |
| 部门级人事审批 | - | 本部门 | - | - |
| HR 复核与离职交接 | - | - | ✓ | 仅显式兼任 HR |
| 档案访问申请和使用 | ✓ | ✓ | ✓ | 不默认开放 |
| 档案访问审批 | - | - | ✓ | 仅显式兼任 HR |
| 部门/企业盘点 | - | 本部门 | 企业范围 | 不默认开放 |
| 合同查看 | 本人 | 本部门 | 企业范围 | 不默认开放 |
| 合同维护 | - | - | ✓ | 仅显式兼任 HR |
| 组织结构配置 | - | - | ✓ | ✓ |
| 账号与角色管理 | - | - | - | ✓ |
| 聚合统计/审计读取 | - | 范围内统计 | 企业统计和审计 | 聚合统计和审计 |

权限要求：前端导航、路由守卫和页面动作与此矩阵一致；Spring Security 的 `@PreAuthorize` 和数据范围继续作为最终授权依据。系统管理员角色本身不再授予 HR 或部门审批权；兼任职责必须显式分配角色。

## 6. 技术结构

```text
web/
├── index.html                    # 登录、工作台选择
├── employee.html                 # 员工自助端入口
├── manager.html                  # 部门工作端入口
├── hr.html                       # 人事运营端入口
├── admin.html                    # 系统管理端入口
└── src/
    ├── api/                      # 共享 API 和类型
    ├── stores/                   # 共享认证状态
    ├── portal/                   # 应用端配置、入口和路由工厂
    ├── layouts/                  # 登录/选择器及四类工作台外壳
    └── views/                    # 业务页与角色首页
```

Vite 负责五个 HTML 入口。业务页面可继续复用现有 Vue 页面，入口路由按应用端显式组装，不再将所有模块挂在共享路由树。共享组件不代表共享导航或共享首页。

## 7. 交付验收

- 每种角色看到正确的应用入口、首页和导航；系统管理员单独登录不能看到 HR 工作台或操作 HR 业务。
- 多角色账号只列出已分配的工作台，工作台切换不重新登录且不扩大后端权限。
- 每个应用端的 HTML 入口可以直接加载和刷新；Hash 子路由刷新不回到根登录页。
- 越权的路由和 API 请求分别被前端和后端拦截。
- 员工、部门、人事和系统首页的首屏任务体现各自用例，不再共用同一套统计概览。
- 登录界面无演示账号或密码样例。
- 既有申请、审批、档案、OCR、合同、盘点和审计闭环继续可通过共享 API 完成。

## 8. 迁移约束

- 保留一个 API 服务和现有数据库关系，不引入新前端运行时依赖。
- 既有业务页面逐步挂入对应门户；不在本次重构中改动 OCR 协议或档案存储格式。
- 系统管理员权限收窄属于安全边界变更；更新控制器授权、状态机角色判定、角色矩阵和现有权限验收代码。
- 演示管理员可维护账号、角色、组织结构和查看审计；业务演示需要显式使用 HR 或部门负责人账号。
